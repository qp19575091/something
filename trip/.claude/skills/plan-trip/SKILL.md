# plan-trip

依使用者需求規劃一趟旅程，產出與 `trip/京都/index.html` 同風格的單檔行程頁。

## 1. 先問清楚

缺什麼就問什麼，不要自己假設：

- 目的地（城市／區域）
- 日期與天數
- 人數、同行者（親子、長輩…）
- 預算等級
- 偏好：景點類型、美食、步調快慢、必去／不去的地方
- 住宿是否已訂

## 2. 查資料

- 營業時間、休館日、票價、交通方式與時間要查證，不憑記憶
- 注意旅行日期的特殊狀況（年末年始、祭典、季節性關閉）

## 3. 產出頁面

建立 `trip/<地點>/index.html`，遵守 `trip/.claude/CLAUDE.md` 的頁面慣例：

- 單檔 HTML，CSS／JS 內嵌，沿用 `京都/index.html` 的 `:root` 變數與版面
- 結構：導覽列 → hero（標題、日期、注意事項）→ 行程總覽卡片 → 每日行程 → 附錄
- 每日行程用表格：時間、地點、內容、交通、備註
- 附錄依需要挑選：住宿建議、票券與交通成本比較、風險清單、預約清單、出發前確認清單、餐廳地圖（Leaflet）

## 4. 收尾

- 在 `trip/.claude/CLAUDE.md` 的「行程索引」加一列
- 告訴使用者哪些資訊尚未查證、哪些需要提前預約

## 修改既有行程

要修改已經存在的 `trip/<地點>/index.html` 時，不必跑上面 1–4 步，改照以下流程：

1. **確認範圍**：先對照「行程索引」找出是哪一趟。要改哪一天、改什麼不清楚時就問；使用者要的是建議時（例如「刪哪個好？」），先提方案，確認後再改
2. **查資料**：新加的景點、餐廳、交通，同樣要查證營業時間、休館日、票價與移動時間
3. **改頁面**：只改相關的段落，其他維持原樣，沿用原本的版面與 CSS 變數。連帶受影響的地方要一起改：
   - 當天時間軸前後銜接、交通方式與時間
   - 行程總覽卡片
   - 地圖標記（Leaflet）
   - 附錄：預約清單、成本比較、風險清單、出發前確認清單
4. **收尾**：
   - 日期或行程名稱有變的話，更新 `trip/.claude/CLAUDE.md` 的「行程索引」
   - 跟使用者說改了哪些地方、哪些資訊還沒查證、哪些要新增預約
